# The Wallace–Simson theorem in Lean 4

A Lean 4 + Mathlib formalisation of the **Wallace–Simson theorem** in the complex plane.

> Let `a, b, c` be pairwise distinct points of `ℂ` and `p` a point with `{a, b, c, p}` concyclic.
> Then the feet of the perpendiculars from `p` to the lines `bc`, `ca` and `ab` are collinear.

The feet are given by an explicit `perpFoot p u v` (characterised by `perpFoot_mem_line` and
`inner_perpFoot`), concyclicity by Mathlib's `EuclideanGeometry.Cospherical`. The key step is the
identity `area2(feet) · D₁D₂D₃ = area2(a,b,c)² · concyc a b c p`, proved by `field_simp; ring`.

**Status:** all statements proved, with no `sorry`. `gate.sh` checks 9 named declarations.

## Main statements

| Lean name | File:line | Statement |
|---|---|---|
| `Simson.simson` | `Simson/Main.lean:64` | Wallace–Simson: distinct vertices and `Cospherical {a,b,c,p}` ⇒ `Collinear ℝ` of the three feet |
| `Simson.simson_area` | `Simson/Main.lean:51` | the same with the circle given as `dist · o = r`, conclusion `area2 (feet) = 0` |
| `Simson.area2_perpFoot_eq_zero_iff` | `Simson/Main.lean:74` | determinant-form converse: for a nondegenerate triangle, `area2 (feet) = 0 ↔ concyc a b c p = 0` |
| `Simson.area2_perpFoot_mul` | `Simson/Identity.lean:43` | the key identity |
| `Simson.perpFoot`, `perpFoot_mem_line`, `inner_perpFoot` | `Simson/Basic.lean:28`, `:50`, `:54` | the foot of the perpendicular and its characterisation |

Only the **forward** direction is proved geometrically; `area2_perpFoot_eq_zero_iff` relates local
expressions and is not the geometric converse ("collinear feet ⇒ `p` on the circumcircle").
Non-vacuity and a negative control are `example`s at the end of `Simson/Main.lean`.

## Verification

`./gate.sh` builds the library and generates its own `#print axioms` queries for 9 named
declarations, fully qualified (every declaration cited in `SPIKE_REPORT.md`, plus every name
queried by the axiom scratch file `scratch/Ax.lean`). The queries are generated by the gate itself, not read
from a file in the repository.

The gate fails if any of the following is true:
- a source file (`Simson/*.lean`, `Simson.lean`) contains `sorry`, `admit`, `native_decide`, `axiom`, `#eval`, `run_cmd`, `initialize`, `IO`, `set_option`, `macro`/`elab`/`syntax`/`notation`/`infix`/`prefix`/`postfix`, `import Lean` or `open Lean`;
- the build fails;
- a named declaration is missing, or has an extra report;
- a named declaration depends on anything other than `propext`, `Classical.choice` and `Quot.sound`.

Output: `PASS (9 declarations, standard axioms only)`. Some of these are definitions, which may
use a subset of the three axioms.

`tests/tamper.sh` plants six kinds of fake proof in scratch copies (in `Simson/Main.lean`) and checks
that the gate rejects each one (a rejection must exit nonzero and print the expected `FAIL`
message). The real repository is never modified.

| Test | What it plants |
|---|---|
| sorry | a `sorry` |
| ax2line | an axiom split across two lines |
| evalfake | an `#eval` that prints a fake axiom report |
| macro | a custom macro that rewrites `#print axioms` |
| falsehyp | the concyclicity hypothesis dropped from `simson` (false: off the circumcircle the pedal triangle is nondegenerate) |
| wrap | a genuine extra axiom with a long name, so the report wraps over several lines |

`tests/tamper.sh` needs a prior `lake build` (it reuses `.lake/build`); run the tests one at a time.

`python3 code/check_simson.py` checks the theorem numerically (2000 random cases, with an
off-circle control); `code/cert.py`, `gen.py`, `gen2.py` derive the identity with SymPy.
`SPIKE_REPORT.md` is the development log (its prior-art section is superseded by the one below).

## Prior art

The Wallace–Simson theorem is **not** new to formal mathematics. The Isabelle AFP entry *The
Wallace–Simson Line Theorem in Isabelle/HOL* (Ramos, Hulak and de Queiroz) uses complex coordinates
and proves the theorem with its geometric converse. Guilhot's Rocq development of oriented angles
proves `droite_Simson` (`point_Simson.v`) as an equivalence, with the extra hypothesis that the
point is not on line `CA`. HOL Light's `Complex/grobner_examples.ml` checks an algebraic encoding.
In Lean, the theorem is not in Mathlib; GitHub code search found only a planning entry with no
proof. As far as we know this is the first Lean proof of the forward direction, and nothing more
is claimed.

## Build

```sh
curl https://raw.githubusercontent.com/leanprover/elan/master/elan-init.sh -sSf | sh   # if Lean is not installed
lake exe cache get
lake build
./gate.sh
bash tests/tamper.sh
```

Toolchain: Lean `v4.33.1`, Mathlib `v4.33.1` (revision pinned in `lake-manifest.json`).
`gate.sh` never fetches: run `lake exe cache get` (or `lake build`) first so that the pinned
Mathlib checkout is present in `.lake/packages`.
